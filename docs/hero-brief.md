# Бриф: hero-секция сайта — покадровая реконструкция

Задача: собрать полноэкранный хедер, визуально неотличимый от референса. Все числа ниже сняты
измерением пикселей с видео шириной **1234 px** и продублированы в `vw`, чтобы масштаб не поехал.
Где указан px «при 1440» — это пересчёт `×1.167`.

Правило: **бриф важнее вкуса**. Не «улучшать» палитру, не скруглять углы, не добавлять
градиентные подложки под текст, не менять сетку. Отклонения допустимы только там, где ниже
явно написано «на выбор».

## 2. Стек

Next.js (App Router) + TypeScript.

```
three
@react-three/fiber
@react-three/drei
@react-three/postprocessing

lenis
```

Канвас монтируется только на клиенте:

```tsx
const HeroCanvas = dynamic(() => import('./HeroCanvas'), { ssr: false })
```

Весь DOM-текст (h1, абзацы, кнопки) рендерится на сервере обычной разметкой и лежит **над**
канвасом. Текст не должен быть частью 3D-сцены — он обязан быть выделяемым и индексируемым.

## 6. Навбар

Тонкий, фиксированный, без фона и без границы снизу. Высота ~40 px (при 1440 — 47 px),
контент вертикально по центру.

- **Вордмарк** слева. Моно или гротеск medium, uppercase, `letter-spacing: .06em`,
  размер `1.06vw` (≈15 px при 1440), цвет белый. Одна из букв заменена на глиф `{{BRAND_MARK}}` —
  сплошная фигура цвета `markBlue` с более светлой внутренней фигурой того же силуэта
  (в референсе — треугольник в треугольнике). Глиф чуть ниже линии капителей, оптически
  выровнен по буквам.
- **Меню** — 4 пункта, отцентрованы **по вьюпорту**, а не по остатку контейнера.
  Моно, uppercase, `0.73vw` (≈10.5 px при 1440), `letter-spacing: .14em`,
  цвет `rgba(255,255,255,.62)`, на ховере — `#fff`, переход 160 ms. Промежуток между
  пунктами ~36 px при 1440.
- **Кнопка справа**: прямоугольник **без скругления**, фон `#D7D7D7`, текст `#0A0A0A`,
  моно uppercase `0.73vw`, паддинг `6px 12px`. Ховер: фон `#fff`.

Навбар не меняет вид при скролле: не появляется блюр, не появляется фон.

Тот же оптический центр.

- Отступ вниз 44 px при 1234 (`3.6vw`).

## 9. 3D-сцена

### 9.1 Рендерер и камера

```tsx
<Canvas
  dpr={[1, 1.75]}
  gl={{ antialias: true, alpha: true, powerPreference: 'high-performance' }}
  camera={{ fov: 45, near: 0.01, far: 100, position: [0, 0, 5.3] }}
>
```

Тонмаппинг выключить (`gl.toneMapping = THREE.NoToneMapping`) — иначе магента выцветает.
Фон канваса прозрачный, за ним работает CSS-градиент.

Радиус сферы = 1. При `fov 45`, `z = 5.3` и высоте вьюпорта 720 это даёт диаметр на экране
≈ 328 px — совпадает с замером референса (320–330 px). Сфера точно в центре кадра.

### 9.2 Точки

- **Количество:** 3200 на десктопе, 1400 на мобильном.
- **Распределение:** сфера Фибоначчи (золотой угол), радиус 1.0, плюс радиальный джиттер
  `±0.02` — иначе видна регулярная спираль.
- **Рендер:** один `THREE.Points` с `ShaderMaterial`,
  `blending: AdditiveBlending`, `depthWrite: false`, `transparent: true`.

Атрибуты на точку: `aSeed` (0..1), `aSize` (0.6..1.0).

**Вершинный шейдер** — задача: размер с учётом перспективы, пульсация, отнесение точки
к «горячей» магентовой зоне.

```glsl
uniform float uTime;
uniform float uPixelRatio;
uniform vec3  uBandAxis;   // ось магентовой зоны, вращается вместе с объектом
attribute float aSeed;
attribute float aSize;
varying float vHot;
varying float vFade;

void main() {
  vec3 p = position;

  // лёгкое «дыхание» оболочки
  p *= 1.0 + 0.015 * sin(uTime * 0.7 + aSeed * 12.0);

  vec4 mv = modelViewMatrix * vec4(p, 1.0);
  gl_Position = projectionMatrix * mv;

  // 0..1 — насколько точка попадает в магентовую зону
  float d = dot(normalize(position), normalize(uBandAxis));
  vHot = smoothstep(0.35, 0.9, d);

  // мерцание
  float twinkle = 0.55 + 0.45 * sin(uTime * 1.6 + aSeed * 40.0);

  // гасим точки, пролетающие вплотную к камере
  vFade = smoothstep(0.15, 0.8, -mv.z) * twinkle;

  gl_PointSize = aSize * (2.6 + 1.6 * vHot) * uPixelRatio * (3.0 / -mv.z);
}
```

**Фрагментный шейдер** — круглый мягкий спрайт, без текстуры:

```glsl
uniform vec3 uCold;   // #AFC0FF
uniform vec3 uHot;    // #FCA8E0
uniform vec3 uDeep;   // #C84F88
varying float vHot;
varying float vFade;

void main() {
  float d = length(gl_PointCoord - 0.5);
  if (d > 0.5) discard;
  float core = smoothstep(0.5, 0.0, d);
  float alpha = pow(core, 1.8);

  vec3 hot = mix(uDeep, uHot, core);
  vec3 col = mix(uCold, hot, vHot);

  gl_FragColor = vec4(col, alpha * vFade * (0.55 + 0.45 * vHot));
}
```

**Магентовая зона.** `uBandAxis` — единичный вектор, вращающийся вокруг оси Y со скоростью
объекта. В кадре магента всегда занимает один сектор сферы (примерно 18 % площади) и уезжает
вместе с вращением. Внутри зоны точки крупнее и ярче, поэтому читаются как короткие
горизонтальные ряды — это следствие сетки Фибоначчи, дополнительно ничего делать не нужно.

### 9.3 Каркас

Это то, что видно и снаружи, и изнутри.

```ts
const geo = new THREE.IcosahedronGeometry(1.02, 3);
// сместить вершины шумом, чтобы силуэт был неровным, а не идеальной сферой
// амплитуда 0.055, простой 3D simplex по позиции вершины
const edges = new THREE.EdgesGeometry(geo, 1);
new THREE.LineBasicMaterial({
  color: 0x6E7AB0, transparent: true, opacity: 0.10,
  blending: THREE.AdditiveBlending, depthWrite: false,
});
```

Неровность обязательна — в референсе силуэт заметно многогранный и слегка мятый.
`detail: 3` даёт размер треугольника, который при пролёте внутрь читается как крупная сетка
на весь экран (как в кадре «внутри»).

### 9.4 Нить (главный акцент)

Светящаяся белая линия, ползущая по поверхности сферы. Снаружи еле заметна, во время
пролёта становится главным объектом кадра.

- Путь: `CatmullRomCurve3`, замкнутая, 8–10 контрольных точек, спроецированных на радиус 1.03,
  контрольные точки медленно дрейфуют шумом → путь всё время меняет форму.
- Геометрия: `TubeGeometry(curve, 220, 0.006, 6, true)`.
- Материал: `MeshBasicMaterial` цвета `#EAF0FF`, `toneMapped: false`. Свечение даёт bloom,
  собственного glow-шейдера не нужно.
- Анимация «прорисовки»: `drawRange` по индексам — видимый участок длиной 35 % от общей,
  движется по кривой за ~6 с, с плавным затуханием на хвосте (альфа-градиент через
  атрибут `aProgress` и простой фрагментный шейдер).
- Яркость линейно зависит от прогресса скролла: `0.35` в состоянии A → `1.0` в момент
  прохождения оболочки → `0.2` внутри.

### 9.5 Орбитальные кольца

Два очень тусклых эллиптических кольца вокруг сферы, радиусы 1.25 и 1.45, наклонены на
разные углы (~20° и ~65°), `LineBasicMaterial` `#6E7AB0` `opacity: 0.06`. Вращаются медленнее
сферы. Они почти не видны, но убирают ощущение «шарик висит в пустоте».

### 9.6 HUD-строки

Это деталь, которая делает картинку узнаваемой. Вокруг сферы плавают мелкие строки
настоящего отладочного вывода.

- **Рендер:** обычный DOM поверх канваса (проще и чётче, чем `Html` из drei), позиции —
  4 фиксированных якоря в процентах от вьюпорта: `(17%, 45%)`, `(69%, 21%)`, `(63%, 68%)`,
  `(31%, 68%)`.
- Моно, `font-size: 0.55vw` (≈8 px при 1440), цвет `rgba(198,202,225,.34)`,
  `letter-spacing: .02em`, `line-height: 1.5`, `white-space: pre`.
- Каждый якорь показывает блок из 2–4 строк, живёт 3–5 с, затем гаснет (250 ms) и
  подменяется следующим блоком из пула. Якоря живут не синхронно.

## 10. Скролл-механика

Автоцикла нет — переход между состояниями управляется скроллом. Всё производное от одного
числа `p ∈ [0,1]`, никаких таймеров, чтобы обратный скролл был точно зеркальным.

**Пин.** Секция-обёртка высотой `260svh`, внутри `position: sticky; top: 0; height: 100svh`.
`p` = прогресс прокрутки внутри обёртки.

Плавность — `lenis` (`duration: 1.1`, `easing` по умолчанию). Значение `p`, приходящее в
сцену, дополнительно сглаживать `damp` (lerp с коэффициентом ~0.12 за кадр).

**Карта состояний:**

| `p` | Камера `z` | Состояние A (opacity) | Состояние B (opacity) | Что видно |
|---|---|---|---|---|
| 0.00 | 5.30 | 1 | 0 | сфера в покое, медленное вращение |
| 0.28 | 4.60 | 1 | 0 | сфера чуть ближе, ничего не меняется |
| 0.38 | 3.40 | 0 | 0 | текст A погас, камера пошла внутрь |
| 0.50 | 1.05 | 0 | 0 | оболочка почти на камере, точки летят мимо, нить на пике |
| 0.58 | 0.35 | 0 | 0.6 | прошли сквозь оболочку |
| 0.68 | 0.10 | 0 | 1 | вид изнутри, текст B на месте |
| 1.00 | 0.10 | 0 | 1 | удержание, затем пин отпускается |

- Кривая `z` — `easeInOutCubic` между узлами, не линейная.
- Непрозрачность текстов: `easeOutQuad`, длительность перехода ≈ 0.08 по `p`.
  Пересечения нет — A гаснет полностью до того, как появится B.
- Вращение сферы идёт **всегда** и не зависит от `p`: `rotation.y += dt * 0.06`,
  плюс `rotation.x = sin(t * 0.25) * 0.08`.
- В момент `p ≈ 0.5` дополнительно поднять `bloom.intensity` с 0.9 до 1.6 и вернуть —
  это даёт вспышку на пролёте.
- Внутреннее состояние (`p > 0.7`) не статично: каркас продолжает медленно вращаться,
  видимые треугольники плывут. Точки почти не видны — их гасит `vFade` из вершинного шейдера.
- Ниже `p = 1` начинается следующая секция страницы, хедер уезжает обычным образом.

## 11. Постпроцессинг

`@react-three/postprocessing`, порядок именно такой:

1. `Bloom` — `intensity: 0.9`, `luminanceThreshold: 0.15`, `luminanceSmoothing: 0.5`,
   `mipmapBlur: true`, `radius: 0.72`
2. `Vignette` — `offset: 0.32`, `darkness: 0.62`
3. `Noise` — `opacity: 0.02`, blend `OVERLAY` (в дополнение к CSS-зерну; если тяжело — оставить
   только CSS-зерно)

Без chromatic aberration, без DoF, без god rays.

## 12. Адаптив

| Брейкпоинт | Изменения |
|---|---|
| ≥1280 | как описано |
| 768–1279 | H1 `clamp` уходит к 44–56 px, `SUB` `max-width: 44vw`, точек 2200 |
| <768 | меню сворачивается в бургер (панель на весь экран, моно-список, фон `#050507`); H1 `34px`, 4 строки; `SUB` `max-width: 80vw`, `bottom: 40px`; состояние B: lead `22px`, body `20px`, `max-width: 88vw`; сфера `scale: 0.78`; точек 1400; `dpr` максимум 1.5; bloom `intensity: 0.7`; HUD-строки — только 2 якоря |

Высоту считать через `100svh`, иначе на iOS будет прыгать при сворачивании адресной строки.

## 13. Производительность

- `frameloop="always"`, но останавливать рендер, когда секция вне вьюпорта
  (`IntersectionObserver` → `gl.setAnimationLoop(null)`).
- Геометрии и материалы создавать в `useMemo`, атрибуты не пересоздавать в кадре.
- Никаких `setState` в `useFrame` — только мутация `ref.current`.
- Целевые метрики: 60 fps на M1 / GTX 1650, ≥45 fps на среднем Android.
  Если ниже — сначала снижать `dpr`, потом количество точек, bloom трогать в последнюю очередь.
- LCP не должен зависеть от канваса: H1 отрисовывается сразу, канвас догружается отдельно
  и появляется через `opacity` за 600 ms.

## 14. Доступность

- `prefers-reduced-motion: reduce`: состояние фиксируется на `p = 0`, пролёта нет, вращение
  замедляется до `0.01 rad/s`, нить статична. Переключение состояний остаётся, но мгновенное,
  через `opacity` без движения камеры.
- `<canvas aria-hidden="true">`. Заголовок — настоящий `<h1>`.
- Фокус на пунктах меню и кнопках виден: `outline: 1px solid #fff; outline-offset: 3px`.
- Контраст `SUB` (`rgba(255,255,255,.46)` на почти чёрном) ниже AA. Если нужно проходить
  аудит — поднять до `.62`, визуально почти не меняется.

## 15. Критерии приёмки

Ставим стоп-кадр рядом с референсом и проверяем:

1. Диаметр сферы в покое ≈ 27 % ширины вьюпорта, центр совпадает с центром экрана.
2. Верхние 60 % полотна — чистый чёрный, синее свечение начинается только снизу и ярче в углах.
3. H1 лежит поверх сферы и частично ею перекрыт; подложки под текстом нет.
4. Подпись состояния A прижата к низу и в разы мельче заголовка.
5. Магентовые точки занимают один сектор сферы и уезжают вместе с вращением, а не мигают по всей поверхности.
6. Каркас — неровный многогранник, не идеальная сфера.
7. Вокруг сферы читаются мелкие строки кода.
8. На пролёте сквозь оболочку белая нить — самый яркий объект кадра.
9. Внутреннее состояние — крупная разреженная сетка на весь экран, не «звёздное поле».
10. Обратный скролл проигрывает всё зеркально, без рассинхрона.
11. Углы у обеих кнопок прямые.

Если пункт не выполняется — чинить его, а не компенсировать соседним эффектом.
